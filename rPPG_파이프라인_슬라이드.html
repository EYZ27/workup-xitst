1. 서비스 이해 및 과제 해결 타겟

비접촉 상태 모니터링 서비스의 신뢰성을 높이기 위한 rPPG 성능 검증

서비스 이해, 현재 문제, 이번 과제의 해결 타겟
1. Camera-Based Vital Sensing 및 Facial Signal Intelligence 기술
— 엑시스트는 일반 카메라와 마이크로 수집한 생체신호·표정·음성·행동 신호를 통합 분석하고, 기존 서비스에 연동할 수 있는 비접촉 상태 모니터링 솔루션을 제공한다.
— rPPG는 이 중 카메라로 심박을 추정하는 핵심 기술이다.
2. 현재 문제
— 주요 rPPG 연구 모델을 자체 학습데이터로 학습 중이나 일정 수준 이후 성능 개선 폭이 제한되고 있다.
— 연구 환경과 실제 웹 카메라 환경의 FPS·조명·움직임·영상 압축 조건이 다르며, 데이터 품질·기준 라벨·타임스탬프 동기화·전처리·평가 방식도 성능 저하에 영향을 줄 수 있을 것으로 예상된다.
3. 타겟별 어려움
타겟해결하고 싶은 문제
서비스 운영자실제 웹 환경에서 비교 가능한 기준 성능과 운영 품질 판단 기준이 부족함
연구개발 조직성능 정체의 원인이 모델 자체인지 데이터·수집·평가 파이프라인인지 구분하기 어려움
사용자측정 실패와 오차로 인해 결과 신뢰도가 낮아질 수 있음
핵심 문제 — 성능 정체가 모델 탓인지 데이터·파이프라인 탓인지 가려낼 재현 가능한 기준 성능이 없다. 이 판단 기준을 세우는 것이 이번 과제의 출발점이며, 그러려면 먼저 rPPG 파이프라인 전체를 이해해야 한다.

2. rPPG 이해 및 성능 저하 원인 구조

rPPG 이해 및 rPPG 측정 파이프라인

배경 원리와 전체 파이프라인 구조
  • 정의 — 카메라로 촬영한 얼굴 영상에서 심장 박동에 따라 발생하는 미세한 피부색 변화를 분석해 생체신호를 추정하는 비접촉 측정 기술이다.
  • 원리 — 모세혈관 혈류량 변화에 따라 피부 반사광 스펙트럼(녹색 파장 대역)이 미세하게(약 0.5% 이내) 변화한다.
  • 근본 난이도 — 신호 대 잡음비(SNR)가 극히 낮아, 이후 모든 파이프라인 단계의 오차가 이 미세 신호를 쉽게 덮어버릴 수 있다.

파이프라인 단계별 핵심 요소와 성능 저하 요인

각 단계에서 성능을 떨어뜨릴 수 있는 요인
단계핵심 요소성능 저하 요인
① 영상 촬영/수집
 FPS·조명·움직임·영상 압축, 자동 노출/화이트밸런스(AGC/AWB) 자동 보정·압축이 미세 색 신호를 왜곡·손실
② 얼굴·ROI 검출/추적
 얼굴 검출기, 랜드마크 ROI(이마·볼), 프레임 추적 검출 실패·ROI 흔들림 → 잡음 유입 · 학습–실서비스 ROI 설정 차이 발생 → 도메인 갭 발생
③ 원시 신호 추출
 ROI 픽셀 채널별 공간 평균, RGB 시계열 생성 ROI 위치·크기 변동이 평균값에 구조적 잡음 유발
④ 신호 전처리
 디트렌딩·정규화, 신호 결합(CHROM/POS 등), 대역통과 필터 필터 대역 이탈로 신호 손실 가능성 존재, 모션 아티팩트 제거에 한계가 있음
⑤ rPPG 신호 추정
 신호처리(CHROM/POS) 또는 딥러닝(DeepPhys·PhysNet 등) 모델 도메인 갭(학습·실환경 분포 차이)을 "모델 한계"로 오인하기 쉬움
⑥ 후처리(BPM/HRV)
 피크/FFT BPM 산출, SQI 기반 저품질 구간 제외·재측정 저품질 구간 미제거 시, 실패가 평균 오차에 반영
⑦ GT 동기화/평가
 참조 장비(ECG/PPG), 타임스탬프 동기화, 지표(MAE·RMSE·bias 등) 수백 ms 동기 오차·GT 라벨 오차가 성능 저하로 오인될 수 있음

단계별 세부 태스크

실험 순서와 각 실험의 세부 태스크
단계 세부 태스크 기대 산출물
Baseline 설정 (1) 데이터 범위·train/val/test 분할 규칙 확정 → (2) 웹앱 조건(FPS·해상도·압축) 정의 → (3) 비교 모델(CHROM/POS·딥러닝) 고정 → (4) 평가 스크립트(MAE·RMSE·bias·Bland-Altman·성공률) 구현 재현 가능한 평가 파이프라인, baseline 성능표·비교 조건 문서
#3 데이터 분할
누수·편향		 (1) 피험자·조명·기기·피부톤 메타데이터 정리 → (2) subject-independent 재분할 → (3) 조건 층화(stratify) → (4) 기존 분할 대비 성능차 측정 누수 없는 분할셋, 기존 성능의 과대평가 여부 판정
#5 타임스탬프
동기화 오차		 (1) 영상–GT 교차상관으로 offset 추정 → (2) 실측 fps로 클럭 드리프트 점검 → (3) 보정 적용 → (4) MAE·RMSE·Bland-Altman 재계산 보정 전/후 지표 비교, 동기화의 성능 기여도 정량화
#4 train↔inference
전처리 불일치		 (1) 학습·추론 전처리 코드 diff(정규화·샘플링·색공간·해상도) → (2) 동일 입력의 중간 텐서 일치 검사 → (3) 불일치 수정 → (4) 재평가 전처리 일치성 리포트, 수정 전/후 성능차
#6 실패 샘플
처리·SQI 부재		 (1) SNR 기반 신호품질지표(SQI) 정의 → (2) 임계값 스윕(coverage-error tradeoff) → (3) 실패/재측정 규칙 수립 → (4) 성공률·오차 분리 리포트 SQI 게이팅 기준, 성공률–MAE 곡선·운영 품질 기준
#1 자동 노출/
화이트밸런스(AWB)		 (1) 고정 API 가능 여부 확인 → (2) 수집 프로토콜 설계 → (3) AE/AWB 고정 vs 자동 대조 수집(동일 피험자 반복) → (4) SNR·MAE 비교·ablation AWB의 영향도 정량화, 웹앱 수집 가이드라인
※ 각 단계는 수용 기준 미달·가설 기각 시 다음 후보로 전환하며, 10~12주차 예비 기간에 결과를 반영해 우선순위를 재결정한다.

4. Baseline 및 가설별 실험 설계

Baseline 설정 설계

모든 개선 실험의 기준선이 되는 재현 가능한 평가 체계 확립
실험 설계 데이터 범위 자체 수집 데이터셋 전체(피험자 수·환경 조건 명시)  →  분할 subject-independent train/val/test(예 60/20/20), 조명·기기·피부톤 층화  →  웹앱 조건 FPS·해상도·압축 코덱을 실서비스와 동일하게 고정  →  비교 모델 전통기법(CHROM/POS)+현재 딥러닝 모델을 동일 조건에서 평가  →  절차 고정 전처리·평가 스크립트화(고정 시드·버전관리)
평가 지표 HR 정확도: MAE · RMSE · bias, Bland-Altman(LoA), 측정 성공률 · 실패율 · 재측정률  |  (가능 시) 파형 상관·HRV
판단 기준
  • 재현성 확보 — 동일 입력 재실행 시 지표 편차 < 1%(결정론적) → baseline으로 확정하고 이후 실험의 기준선으로 사용
  • 재현 불가·분산 큼 — 파이프라인 결함(시드·데이터 로딩·평가 코드)을 우선 수정 후 재확립
  • 확정된 baseline 성능을 문헌·내부 목표와 비교해 개선 여지의 위치를 명시
근거자료 Liu et al. (2023), "rPPG-Toolbox", NeurIPS D&B — 입력 정규화 3종·Butterworth 0.75–2.5Hz 필터·FFT/피크 BPM 산출·cross-dataset 평가를 재현 가능 baseline의 표준 프로토콜(reference implementation)로 제시.  |  Elgendi et al. (2026), npj Digital Medicine — HR 지표(MAE·RMSE·Bland-Altman) + 신호수준 지표(PCC·SNR)를 함께 보는 다중 지표 평가 권고.

4. Baseline 및 가설별 실험 설계

#3 데이터 분할 누수·편향 — 실험 설계

기존 성능이 착시(과대평가)인지 먼저 판별
실험 설계 피험자·조명·기기·피부톤 메타데이터 정리  →  기존 분할 vs subject-independent 재분할 A/B 비교  →  조건 층화(stratify) 후 그룹별 성능 측정  →  동일 피험자 train/test 혼입(누수) 감사
평가 지표 MAE · RMSE(전체 및 조건 그룹별), 그룹 간 성능 격차, 기존 분할 대비 성능 변화폭
판단 기준
  • 채택 — subject-independent 전환 시 성능이 크게 하락(예 MAE +2bpm↑) → 누수 확정, 재분할셋을 새 baseline으로 교체
  • 수집 보강 — 그룹 간 격차가 큼 → 데이터 대표성 문제로 수집 보강 우선순위 상향
  • 기각 — 변화 미미 → 분할은 원인 아님, 다음 가설로 이동
근거자료 Liu et al. (2023), "rPPG-Toolbox", NeurIPS D&B — 기존 관행(학습·테스트 세트 불일치, 신뢰 불가 라벨의 임의 필터링)이 보고 성능을 실제 일반화와 괴리시킨다고 지적하고, cross-dataset 평가(한 데이터셋 학습 → 다른 데이터셋 평가)를 표준 프로토콜로 제시.  |  remotebiosensing/rppg — 공정 평가용 국내 벤치마크 프레임워크.

#5 타임스탬프 동기화 오차 — 실험 설계

"모델이 아닌 채점의 오류" 배제
실험 설계 영상–GT 교차상관으로 최적 offset 탐색  →  실측 fps로 클럭 드리프트 추정  →  상수 offset vs 드리프트 분리  →  보정 전/후 동일 데이터 재평가
평가 지표 MAE · RMSE · bias, Bland-Altman LoA, (가능 시) 파형 상관 · IBI 오차(beat-level에서 민감)
판단 기준
  • 채택 — 보정 후 RMSE·LoA가 유의 개선(예 RMSE −20%↑) → 동기화가 주요 병목, 파이프라인에 보정 상시 적용
  • 수집 개선 — 드리프트 확인 시 → 수집 단계 클럭 동기화(하드웨어 트리거 등) 개선 요구
  • 기각 — 보정해도 변화 없음 → 동기화는 원인 아님, 다음 가설로
근거자료 Mironenko et al. (2020), "Rarely Considered Factors", CVPRW — 롤링 셔터로 최대 0.02초 위상 편이 발생(심박 위상 이동과 동급 크기), 시간 윈도우 크기에 따라 산출 HR이 최대 4–10 bpm 차이 → 비교 실험 시 윈도우·동기화 조건 명시 필요. (동일 연구는 불규칙 프레임레이트의 영향은 미미하다고도 보고)

#4 train↔inference 전처리 불일치 — 실험 설계

모델을 손대기 전, 저비용·고효과 항목 배제
실험 설계 학습·추론 전처리 코드 diff(정규화·프레임 샘플링·색공간·리사이즈)  →  동일 입력의 중간 텐서 수치 비교  →  불일치 항목을 하나씩 정렬하는 ablation  →  수정 후 재평가
평가 지표 중간 텐서 max/mean 절대오차(일치성), 항목 정렬 후 MAE · RMSE 변화
판단 기준
  • 채택 — 정렬 후 성능 개선 → 불일치가 원인, 즉시 수정(저비용 고효과)
  • 부분 수정 — 일부만 개선 → 기여 항목을 식별해 우선 수정
  • 기각 — 중간값 완전 일치인데 성능 그대로 → 원인 아님, 모델·데이터 쪽으로 이동
근거자료 Liu et al. (2023), "rPPG-Toolbox", NeurIPS D&B — 모델·전처리·후처리·하드웨어가 섞여 성능차 원인을 특정할 수 없는 "apples vs oranges" 비교 문제를 명시하고, 입력 정규화 3종(Raw/Standardized/DiffNormalized)·얼굴 크롭 방식·후처리(Butterworth 0.75–2.5Hz→FFT/피크)를 표준화 → 전처리 일치성 검증의 참조 구현으로 활용 가능.

#6 실패 샘플 처리·SQI 부재 — 실험 설계

실패가 평균 오차를 부풀리는지 분리해 확인
실험 설계 SNR 기반 신호품질지표(SQI) 정의  →  임계값 스윕으로 coverage-error tradeoff 곡선 작성  →  SQI 게이팅 전/후 성능·성공률 비교  →  실패/재측정 규칙 시뮬레이션
평가 지표 성공률 · 실패율 · 재측정률, coverage별 MAE, 게이팅 후 MAE 개선폭
판단 기준
  • 채택 — 저품질 구간 제외 시 MAE 크게 개선 & 성공률 허용 범위 유지(예 성공률 ≥ 85%) → 게이팅 기준을 운영 품질 기준으로 반영
  • 임계값 재조정 — 성공률 과도 하락 → coverage-error 균형점으로 임계값 조정
  • 기각 — 게이팅해도 개선 미미 → 실패 처리 아닌 다른 원인
근거자료 "Optimal signal quality index for rPPG" (2024), npj Biosensing — 8종 SQI 비교 검증에서 SNR 기반 NSQI가 품질 구간 판별에 최우수, 임계값 NSQI < 0.293에서 고품질 구간을 효과적으로 선별(Leave-one-out 교차검증) → 임계값 스윕 실험의 구체 출발점.  |  Reliability factor for rPPG (ACM, 2023) — 신뢰도 지표 기반 결과 게이팅.

#1 자동 노출/화이트밸런스(AWB) — 실험 설계

파이프라인·평가 오류 배제 후 남는 실제 환경 원인 규명
실험 설계 고정 API 가능 여부 확인  →  수집 프로토콜 설계  →  AE/AWB 고정 vs 자동 대조 수집(동일 피험자·자세 반복)  →  SNR·성능 비교, 압축·조명과 교차 ablation

판단 기준
  • 채택 — 고정 조건에서 SNR·MAE 유의 개선 → AWB가 도메인 갭 주원인, 수집 가이드에 고정(또는 색 안정화 보정) 반영

AI와 휴먼의 판단 과정

7. 종합 요약

종합 요약 — 무엇을, 왜, 어떤 순서로

"성능 저하 = 모델 한계"로 성급히 단정하지 않고, 병목을 순서대로 배제한다

핵심 접근

  • 재현 가능한 baseline을 먼저 확립해 "채점"을 신뢰 가능하게
  • 저비용·고ROI 평가·파이프라인 오류부터 배제
  • 남는 실제 환경 원인(AWB 등)을 겨냥
  • 모델 재학습은 마지막 — 예비 기간에 결과 보고 판단

3개월 산출물

  • 웹앱 조건에서 재현 가능한 baseline 성능·비교 조건
  • 우선 5개 가설의 검증 결과와 병목 규명
  • 지표별 수용 기준과 결과별 의사결정 기준
  • 협업·위험 대응을 포함한 실행 계획서

의사결정 원칙

  • 각 실험은 수용 기준으로 채택·기각 판정
  • 가설 기각 시 다음 후보로 전환
  • 지표는 MAE+bias+Bland-Altman+성공률 병행
  • 문헌 수치는 초기값, 자체 데이터로 재튜닝
한 줄 결론 — 신뢰할 수 있는 채점 → 싼 검증 → 비싼 검증 → (필요 시) 모델. 이 순서가 곧 영향도·불확실성·실행비용을 반영한 우선순위다.
